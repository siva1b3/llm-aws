# Project Instructions

## On Agent Startup

Read `protected/laws.md` and `protected/file_structure.md` when the agent starts. Keep their instructions in context throughout the session. Read them again if they change or are no longer available in context.

## Read According to the Request

After startup, load only the files relevant to the request:

| Request | Files to read |
| --- | --- |
| What is the current state? | `current_state.md` |
| What are the next action items? | `action_plan.json` |
| What is the goal or who is involved? | `protected/goal.md` |
| How does the workflow operate? | `protected/workflow.md` |
| Propose, revise, or execute action items. | `protected/goal.md`, `protected/workflow.md`, `current_state.md`, `action_plan.json`, and relevant implementation files. |

For requests covering several topics, read the corresponding files. Reuse contents already available in context unless they may have changed. Do not load unrelated files.

## Governing Rules

The laws govern all project work. The goal defines the destination; the workflow defines the process; the state and plan record progress and next actions.

Follow the file locations and permissions in `protected/file_structure.md`. Do not edit this file without explicit human authorization.

Create known missing placeholders according to the file structure rules. If instructions needed for the requested work are missing or contradictory, ask the human to supply or clarify them before executing that work.
