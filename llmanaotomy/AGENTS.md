# Agent instructions

This file is the entry point for agents working in this workspace.
Use the three context folders to understand the project and resume work.

## Reading order

1. Read [current progress](project-status/current-progress.md) for the active task, learning boundary, blockers, and next action.
2. Read the [project guide](project-rules/project-guide.md) for the goals, scope, teaching agreement, and success criteria.
3. Read the [technical reference](project-rules/technical-reference.md) when technical choices or runtime settings apply.
4. Read the [evidence index](project-evidence/README.md) and relevant records before relying on earlier conclusions.

Use [project-context-guide.md](project-context-guide.md) for the organizing principles behind these folders.
Use [asd-ste100.md](asd-ste100.md) as the writing reference when relevant.
Do not modify either reference unless the user explicitly requests it.

The [source comparison](project-evidence/context-reorganization.md) maps the six supplied source files to the current documents.
Treat `sources/` as reference material. Maintain current rules, status, and findings in the three context folders.

## Folder responsibilities

| Folder | Purpose | When to update |
| --- | --- | --- |
| [project-rules](project-rules/README.md) | Agreed goals, scope, constraints, working agreements, and technical choices | When an agreement or governing decision changes |
| [project-status](project-status/README.md) | Active work, verified progress, unresolved questions, blockers, and the next action | After meaningful work or a change in current state |
| [project-evidence](project-evidence/README.md) | Methods, observations, results, explanations, and limitations that support conclusions | When actual work produces useful evidence or corrects a finding |

## Working rules

- Follow the applicable project agreements before implementing or explaining the next operation.
- Respect the current learning boundary and the learner confirmation gates in the project guide.
- Resume from the last verified, learner-confirmed boundary. Do not restart completed work or expose multiple new operations together.
- Distinguish planned work, implementation, execution, technical verification, and learner confirmation.
- Label assumptions, expectations, illustrative examples, and observed results clearly.
- Never invent execution results, environment details, or learner confirmations.
- Treat selected configuration as a choice until actual evidence verifies it.
- Keep changes limited to the authorized task and directly relevant files.
- Preserve the existing folder structure unless the task requires a change.

## Maintaining context

- Keep each rule or fact in one authoritative document. Link to it elsewhere.
- Replace outdated current status instead of adding a history of competing checkpoints.
- Keep detailed findings in evidence records. Summarize relevant conclusions in current status.
- Record the question, conditions, method, observations, interpretation, and limitations when they apply.
- Preserve useful evidence. Explain corrections and identify superseded conclusions.
- Keep active questions and blockers in current status. Link to related investigation records.
- Update governing agreements only after an agreed decision. Evidence alone does not authorize a new objective.
- Do not create empty evidence records or extra files without a concrete need.
- Do not update context files merely because they were read. Respect requests that limit edits to specific files.

Write direct instructions and concise explanations. Preserve uncertainty and technical meaning.
Limit instruction sentences to 20 words and description sentences to 25 words when precision permits.
Do not claim ASD-STE100 compliance without the required standard and review.
