# Project status

This folder contains current state: active work, progress, verified results, unresolved questions, blockers, and the next action.

Read [current-progress.md](current-progress.md) first.
Use it to resume work without reconstructing a history of updates.
Replace outdated status after meaningful work, failure, learner confirmation, or a session handoff.

Read [hld.md](hld.md) for high-level design progress and unresolved component boundaries.
Read [lld.md](lld.md) for low-level design progress and unfinished interface details.
These files own design-specific state. The overall checkpoint remains in current progress.
Update them after relevant design work, execution, verification, or an agreed decision.
Read HLD status before LLD status when both affect the current work.

Keep governing agreements in [project-rules](../project-rules/README.md).
Keep detailed observations and earlier findings in [project-evidence](../project-evidence/README.md).
Link to evidence rather than copying logs into status.

Keep planned, implemented, executed, technically verified, and learner-confirmed states distinct.
An unanswered question belongs here when it affects active work or the next decision.
A proposed agreement change remains here until the decision updates its rule owner.

Return to [AGENTS.md](../AGENTS.md) for routing.
