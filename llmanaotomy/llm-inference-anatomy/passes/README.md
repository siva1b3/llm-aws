# Pass records

Follow the local [operating instructions](../AGENTS.md). Each pass has one clear outcome, an approved plan, recorded checks, and a closing decision.
The reserved `pass-001` is inactive. Its four records intentionally remain at zero bytes.

Propose a bounded outcome before drafting actions. Record planning authority before activating the reserved pass.
Draft the plan and expected checks, then obtain separate execution approval for that revision.
Do not ask again for unchanged work already authorized.
Keep only one pass active, including while paused or blocked.
Close it before starting another with human confirmation.

| Record | Responsibility |
| --- | --- |
| plan.md | Outcome, criterion links, revision, actions, progress, assumptions, design references, limits, and approvals |
| verification.md | Expected and actual results, context, limitations, reviews, and closure decision |
| findings.md | Detailed observations and unresolved questions |
| evidence.md | Index and context for supporting evidence retained directly in the pass folder |

Use sequential identifiers; never reuse one for unrelated work. Do not create subfolders inside a pass.
Later passes require plan and verification records; add findings and evidence only when needed.
Keep application and design deliverables in agreed project locations, with links from pass records.
Preserve failed checks, prior approvals, and closed history.
Record each material check's ID, related criterion, method, expectation, observation, status, context, evidence, and limitation.
Use successful, unsuccessful, deferred, or cancelled for closed outcomes.
After closure, update current state and preserve remaining criteria and next action.
