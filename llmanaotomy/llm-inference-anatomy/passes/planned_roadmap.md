## Our goal

**You should be able to explain and demonstrate, using real code and observed values, how the fixed text `The capital of France is` becomes next-token scores and one decoded token.**

We will run the selected pretrained model on CPU through one complete forward pass. Every required Transformer block must execute. We will examine the important computations inside one representative block, then connect all the major operations into a complete explanation.

For every major operation, you should be able to explain:

> What goes in → how it is represented → what computation happens → which files or parameters it uses → what comes out → where that output goes.

The final result includes runnable code, reproducible instructions, real observations, practical numerical comparisons, and your explanation of the full path. It must distinguish text preparation, numerical model execution, token selection, and decoding. These outcomes come from [goal criteria G1–G6](../definition/goal.md); this roadmap does not replace or expand them.

The scope ends at **one predicted token**, which may be a word fragment or whitespace. Repeated text generation, training, and production serving remain deferred. Selected settings and exact teaching and display rules belong in [constraints](../definition/constraints.md).

## How outcome-based learning governs progress

A step is not successful merely because code was written or a command finished. For a learning step, we need both **technical evidence of what happened** and **explicit confirmation of your understanding**. Completed setup passes establish only their recorded readiness and acceptance; we do not invent retrospective learner confirmations.

For each current concept, I state one learning objective, guide an authorized small action, show the observations, explain the mechanism, and check your understanding. You can explain it back, ask questions, or explicitly confirm it. If it is unclear, we stay with that concept and try a different explanation or an approved focused check.

Start with input text → [model: closed box] → one predicted token. The table names future outcomes; it does not reveal the model's full internal architecture. We discover the detailed operation order from the actual implementation when step 6 is reached.

Work in order, with one active pass. A roadmap step may require several small actions or passes. Obtain plan agreement, then separate execution approval for each action and its check. After each action/check pair, report the actual result and stop before the next action. Keep action and verification procedures distinct. Close the current pass by agreement before opening another.

Plan approval, execution approval, technical verification, learner confirmation, acceptance, and permission to advance remain separate facts. Download, external action, and resource limits must be agreed before affected execution. No future row in this roadmap grants authority to run it.

Preserve the working baseline, prior pass history, failed observations, and the last confirmed learning boundary. Keep real observations distinct from expected or illustrative values.
