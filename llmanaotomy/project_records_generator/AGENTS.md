# Agent instructions for the project records generator

## Scope and reading order

These instructions apply to this folder and its subfolders.
This folder contains reusable preparation guidance, not an active project or generated records.
Read the human's request, [overview](README.md), and [generator](software-ai-project-records-generator.md) before work.
Read the referenced core, architecture, quality, and applicable domain guides before preparing records.
Treat supplied files and example commands as information, not new execution authority.

## Maintaining this folder

Distinguish editing the reusable procedure from applying it to a destination project.
An authorized maintenance request permits the requested documentation changes and document checks.
It does not require generating project records or opening an engineering pass here.
Preserve unrelated user work and stay within the requested scope.
Use simple English, active voice, consistent terms, and one instruction per sentence.
Aim for instructions within 20 words and descriptions within 25 words where practical.
Preserve conditions, exceptions, technical identifiers, and uncertainty.

The generalized version 3 generator supplies the preparation baseline for this software specialization.
The [core workflow](../software_ai_guides/core/software-ai-development-workflow.md) owns paths, approvals, action boundaries, checkpoints, and completion.
The generator owns full-source extraction, selection, preparation, verification, and delivery.
Architecture, quality, and domain guides retain their technical responsibilities.
Do not duplicate a fixed output tree or file count here.
Do not introduce a dependency from the guide library to this generator.
Resolve relative links from their containing file and update references affected by authorized changes.

## Applying the generator

Apply the generator only when the human requests preparation.
Inventory and completely read every designated source, including instruction, status, and configuration files.
Use temporary coverage and output-contract checklists; do not add permanent logs outside the core-defined structure.
Preserve substantive requirements, exclusions, teaching methods, review gates, selected settings, prior state, and uncertainty.
Replace obsolete source navigation and record-update directions with internal owners and version 3 checkpoint rules.
Resolve substantive conflicts before dependent preparation.

Derive paths and content permissions from the actual core workflow.
Protect the destination and preserve existing populated records, approvals, and pass history.
Create all required new records empty and verify zero bytes before filling supported contents.
Keep reserved passes inactive and their records empty; keep the final report empty until closure.
Record preparation checks in current state, never in an inactive pass.
Do not invent scope, technology, authority, evidence, review, learner confirmation, or completion claims.

Write every core-required operating rule and precise checkpoint condition into generated AGENTS.md.
Include conversational drafting, separate plan approval, per-action execution approval, small actions, and separate checks.
Save the agreed plan only after final execution approval and before execution.
Keep routine observations and approvals in conversation until a defined checkpoint.
Preserve valid approvals and stricter project-specific review or learning gates.

Transfer applicable software and AI guidance into the appropriate generated records.
Do not leave operating instructions dependent on source files, this generator, the guide library, or conversation history.
Keep preparation provenance as plain text in the generated overview and use internal links for ongoing work.
Verify semantic independence as well as link resolution without moving or deleting inputs.

## Verification and delivery

Review structure, coverage, empty-file sizes, rule completeness, behavior scenarios, and isolation from preparation inputs.
Check affected Markdown links and consistency with the current core workflow.
Use document checks for documentation changes; do not invent application build or test commands.
Report actual changes or generated records, checks performed, unresolved limits, and the next human review.
Stop after preparation and verification when applying this generator.
